# Family Dent Marketing

Внутреннее приложение команды маркетинга: шесть направлений, контент-план, согласования, задачи, еженедельные отчёты, расходы, врачи, партнёры, события и идеи.

Стек: HTML/CSS/JavaScript + Node.js 22, Supabase Auth/PostgreSQL, GitHub, Render. Рабочее приложение не требует внешних JS-пакетов или сторонних CDN.

## Локальный просмотр

```sh
npm ci
npm start
```

Откройте http://localhost:3000. Без ключей Supabase на локальном компьютере включается явно обозначенный демонстрационный режим. Все числа и карточки врачей в нём вымышлены, а изменения сохраняются только в localStorage этого браузера. Переключатель позволяет проверить роли. В production демо выключено.

## Подключение Supabase

Проект: `https://fpaxovjmfynavxnosdsq.supabase.co`.

1. В SQL Editor выполните по порядку `supabase/migrations/001_initial.sql`, `002_content_and_security.sql`, затем `supabase/seed.sql`. Миграции предназначены для новой схемы: при совпадении существующих таблиц сначала выберите отдельный проект или проведите проверку конфликтов. Ничего в существующей базе автоматически не удаляется.
2. Скопируйте `.env.example` в `.env`. Заполните SUPABASE_URL и SUPABASE_ANON_KEY. Ключ service_role нужен серверу только для подключения Meta и worker; обычные запросы идут с JWT сотрудника и подчиняются RLS.
3. Включите email/password Auth. Отключите свободную регистрацию. Настройте SMTP, Site URL и разрешённые Redirect URLs на адрес Render (и localhost для тестирования).
4. Создайте первого сотрудника через Supabase Authentication. В `profiles` добавьте его `auth.users.id`, имя, роль `marketer` и `active=true`. Никто не может выдать себе роль из интерфейса.
5. Сотрудников можно приглашать из терминала оператора: `node --env-file=.env scripts/provision-user.mjs email "Имя" leadership`. Команда отправляет реальное письмо, поэтому используйте её только для согласованного сотрудника. Из приглашения пользователь устанавливает пароль; есть восстановление доступа.

Роли: `marketer`, `leadership`, `staff`, `doctor`, `it`. Сомон получает `leadership`. Все реальные сотрудники создаются индивидуально, без общих паролей. В seed нет пользователей, финансов или строк пациентов.

## Render

В репозитории приложение находится в `apps/family-dent-marketing`. Создайте Blueprint, указав путь `apps/family-dent-marketing/render.yaml`, либо создайте Web Service и Cron Job вручную с Root Directory `apps/family-dent-marketing`.

- Web Service: build `npm ci --ignore-scripts`, start `npm start`, health `/health`.
- Cron Job: build `npm ci --ignore-scripts`, start `npm run worker`, расписание `*/5 * * * *` (UTC). Отправка очереди проверяется каждые 5 минут; статистика собирается примерно раз в час.
- Заполните переменные из `.env.example` в панели Render. Для web и cron используйте одинаковый TOKEN_ENCRYPTION_KEY. Генерация: `node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"`.
- Установите APP_URL на фактический HTTPS-адрес сервиса, ALLOW_DEMO=false, NODE_ENV=production.
- Тарифы в Blueprint платные (`starter`): стоимость и создание сервисов подтверждает владелец в Render. Автоматический деплой в этой поставке не выполняется.

## Meta и Google Drive

1. Создайте приложение Meta для компании и настройте Facebook Login. Этот вариант подключения Instagram требует профессиональных аккаунтов, связанных с Facebook Pages.
2. Callback: `https://АДРЕС-ПРИЛОЖЕНИЯ/api/meta/callback`. Настройте META_APP_ID, META_APP_SECRET, META_GRAPH_VERSION (поддерживаемая версия из панели Meta), TOKEN_ENCRYPTION_KEY и необходимые разрешения. Для production могут потребоваться App Review и проверка компании.
3. В настройках приложения нажмите «Подключить Meta». Подключаются только зарегистрированные аккаунты, сопоставленные по идентификатору или точной ссылке/username. Вторая Facebook-страница пока без направления.
4. Ключи Meta шифруются AES-256-GCM и лежат в закрытой схеме `private`. Браузер их не получает. Недействительный ключ отображается как ошибка подключения; повторите подключение. Автоматическое продление долгоживущих ключей пока не реализовано.
5. Храним только ссылки на материалы. Ссылки Google Drive `/file/d/ID/view` преобразуются в ссылки скачивания, но файл должен быть доступен Meta без входа. Закрытый Drive и экраны подтверждения скачивания не поддерживаются. Для них потребуется отдельное разрешённое подключение Drive или доступная HTTPS-ссылка на файл. Не делайте публичными материалы с личными данными пациентов.
6. Сначала проверьте реальные тестовые фото и видео на согласованных аккаунтах. Только затем включите META_PUBLISHING_ENABLED=true одновременно на web и cron.

Реализован код отправки одиночного фото и Reels в Instagram, одиночного фото с текстом в Facebook. Карусели, сторис, видео Facebook, музыка и интерактивные элементы требуют дальнейшей реализации/проверки; для них предусмотрена ручная публикация с сохранением ссылки. Все форматы используют контент-план и согласования. Боевой вызов Meta в этой поставке не проверен из-за отсутствия ключей и разрешений. Зависший запрос не повторяется автоматически: статус `uncertain` защищает от дублей.

Сбор статистики получает число подписчиков, охват Instagram и доступные метрики последних 25 публикаций, взаимодействия Facebook. Версия API и права могут ограничить показатели. Данные — снимки с временем обновления, не поток в реальном времени; вся историческая статистика задним числом не обещается. Отклонённые метрики не заменяются нулями. Часть недоступных метрик требует корректировки списка после проверки живых аккаунтов. Рекламные расходы вносятся вручную; Marketing API рекламного кабинета отдельно не подключён.

## Финансы и приватность

- Только сводные числа: неделя, филиал, направление, источник, количество и суммы. ФИО, телефоны, диагнозы и строки пациентов не импортируются.
- Оплаты первичных пациентов — выручка без вычета лечения, не прибыль.
- Деньги доступны только активным `marketer` и `leadership`. `it` сам по себе не получает финансы. Ограничения действуют на сервере и в RLS, включая прямые REST-запросы.
- Еженедельный отчёт и оплаты сохраняются атомарно. Повторный ввод тех же измерений обновляет запись.
- Два разных действующих руководителя одобряют план. Голос врача не заменяет руководство. Изменения текста и видео не сбрасывают одобрение — согласно согласованному правилу.
- Все суммы TJS. Общие расходы не распределяются автоматически. Расходы по филиалу не показываются, пока нет правила их распределения.
- CSV защищён от выполнения формул при открытии в Excel. Сессии хранятся в HttpOnly cookies, сервер проверяет Origin для изменяющих запросов.
- История изменений и версий хранится в базе. Резервное копирование, сроки хранения и удаление данных настраиваются владельцем Supabase перед запуском команды.

## Проверки

```sh
npm run check
npm test
```

Для интеграционных проверок SQL установите тестовую библиотеку локально: `npm install --no-save --package-lock=false @electric-sql/pglite` и повторите `npm test`. Без неё тест базы будет явно пропущен; HTTP и проверки правил выполняются всегда. Можно указать PGLITE_MODULE с абсолютным путём к `dist/index.js`.

Тест базы поднимает изолированный PostgreSQL в памяти, применяет миграции и проверяет RLS, запрет повышения роли, два голоса руководства, историю материалов и атомарность отчётов. Реальный Supabase тесты не затрагивают. Перед рабочим запуском дополнительно проверьте RLS в самом проекте Supabase и интеграцию Meta.
